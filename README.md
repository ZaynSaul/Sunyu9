# Sunyu9

An offline-first mobile app that helps people in The Gambia upgrade their phone
contacts from the old **7-digit** numbers to the new **9-digit** format.

It scans the phonebook on the device, finds numbers that still use the old
format, shows a preview of every proposed change, updates the contacts you
approve in bulk, and lets you undo. **Contacts never leave the phone** — there is
no account, no server, and no network calls.

```
Phone contacts → read → detect → convert → preview → update phone contacts
```

## Status

**Milestones 1–4 done** — the full flow works end to end: scaffold → permission →
read/display → numbering engine → scan → preview → confirm → **write + backup →
success + undo**.

Implemented:

- Expo Router app shell, theme, and screen flow (`app/`)
- Contact permission flow with an explanation screen and a Settings deep-link
  when access is blocked (`hooks/useContactPermission.ts`, `app/permission.tsx`)
- Paged contact reader built on the SDK 57 `expo-contacts` class API, with scan
  progress (`services/contacts/contactReader.ts`, `contactMapper.ts`)
- Windowed contact list for large address books (`components/contacts/`)
- **Numbering engine** — `normalize → validate → classify → convert → re-validate`,
  conservative by design (`services/numbering/`)
- **Scan + preview** — per-number analysis with progress, a review screen showing
  every `old → new` change (and every skipped number, greyed, with a reason),
  per-number / per-contact / all selection, and a bottom-sheet confirmation
  (`services/contacts/contactAnalyzer.ts`, `store/analysisStore.ts`,
  `app/scan.tsx`, `app/results.tsx`, `components/conversion/`)
- **Write + backup + undo** — `patch({ phones })` rebuilds each contact's full
  phone list (unchanged rows kept, selected rows swapped to the converted
  `target`). Before/while writing, each affected contact's *complete* original
  **and** new phone list is saved to AsyncStorage (`migration:last`), persisted
  every 20 contacts so an interrupted run still has a usable Undo. The success
  screen shows the count, any failures, an **Undo** (exact snapshot restore),
  **Retry failed** (re-runs only the failed contacts, appends to the same
  backup), and **Save backup file** (CSV via the share sheet — no network).
  (`migrationPlan.ts` / `contactBackup.ts` / `backupExport.ts` (pure parts tested),
  `contactUpdater.ts` (the only writer), `store/migrationStore.ts`,
  `app/updating.tsx`, `app/success.tsx`)
- **Settings → Last update** — the backup survives app restarts
  (`migrationStore.hydrateBackup`), so Undo and CSV export stay available later
  (`components/conversion/LastMigrationCard.tsx`)
- 62 unit tests across the engine, analyzer, migration planner, and CSV export
- Numbering-plan reference data + a Settings info screen
  (`constants/numbering.ts`, `app/settings.tsx`)
- Trust hardening: shipping builds (`preview` / `production` EAS profiles) block
  all networking permissions via `app.config.js`, so the OS app-info screen
  proves the app cannot upload anything

Runs end to end on a physical Android device (debug prebuild).

Next up: a no-permission "paste a number" lookup screen (funnel + trust);

CSV bulk-convert mode; iOS device pass.

## The numbering plan

PURA (Public Utilities Regulatory Authority) is expanding Gambian mobile numbers
from 7 to 9 digits. The existing 7-digit number is kept intact and a **2-digit
operator prefix** is added in front:

From PURA's own [Numbering Resource Management](https://pura.gm/ict/scarce-resource-management/numbering-resource-management/)
allocation table (the notice's worked example `7xx xxxx → 87 7xx xxxx` confirms it):

| Operator | Old 7-digit starts with | New prefix |
| --- | --- | --- |
| Africell | `2`, `4`, `7` | `87` |
| QCell | `3`, `5` | `83` |
| Comium | `6` | `86` |
| Gamcel | `9` | not migrating in this phase |
| Gamtel (fixed line) | `8` | not a mobile migration |

Timeline: both formats route from **2026-09-04**; old 7-digit numbers stop
connecting after **2026-11-30**.

`NUMBERING_VERIFICATION.status` is `'confirmed'`. The `4xxxxxx` and `5xxxxxx`
blocks (historically Gamtel's) were reallocated — `4` to Africell, `5` to QCell —
and migrate accordingly; Gamtel keeps only `8xxxxxx`. The conversion policy stays
conservative: the engine re-validates every result and unrecognised numbers are
left untouched.

## Development

This is a **prebuild (bare-workflow) app**, not an Expo Go / dev-client app — it
reads and writes device contacts, so it needs real native code. `android/` and
`ios/` are generated by `expo prebuild` and are git-ignored (Continuous Native
Generation); run prebuild whenever `app.config.js` or native deps change.

```bash
npm install

# Generate native projects + build + run a debug build (needs Android SDK / Xcode)
npm run android            # expo run:android   (keeps INTERNET for Metro)
npm run ios                # expo run:ios

# Just (re)generate the native projects
npm run prebuild:android   # expo prebuild -p android --clean

# Release build — strips INTERNET / network permissions (APP_VARIANT=release)
npm run build:android:release
```

EAS profiles ([eas.json](eas.json)): `development` (debug APK), `preview`
(release APK, internal), `production` (release AAB). `preview` / `production` set
`APP_VARIANT=release`, which blocks all networking permissions in the manifest.

Other commands:

```bash
npm run typecheck   # tsc --noEmit
npm test            # jest
npm start           # Metro (for an already-installed build)
```
